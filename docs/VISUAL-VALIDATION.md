# SkyCaptain 视觉验收范围

## 验证对象

- SkyTrans 316 秒演示的 3/2 m/s 垂直速度、暂停/seek/倍率和完整停车时序。
- 1× 巡航时可辨识的两个前桨扫掠层；后桨停转/折叠。0.1× 显示实体叶片，暂停与停车不残留曝光层。
- Low / Medium / High 场景与模型实际渲染，含共享地形、河湖、道路、村镇与林木。
- 两机型白色航迹的世界坐标、独立仿真时间、暂停、seek、数据源/控制权和机型切换生命周期。
- 新旧名称、静态资源、SDK/wire 协议和同一租约/去重/epoch 行为。

真实浏览器用例不仅断言页面文字或 HTTP 200，还等待新渲染帧、真实 draw calls、模型状态与相机过渡；同时收集 pageerror 和 WebGL shader 编译错误。

## 截图与可复查数据

`Verify integrated aircraft browsers` 在每次 push 及面向 main 的 PR 运行单 worker Chromium + SwiftShader，上传 `hangar-browser-evidence` artifact：

- 0.1× 运行中的上升阶段：速度 HUD 与实体桨叶。
- 1× High 跟随巡航：前桨/后桨与近处地形。
- 普通本地 valley 航线约 173.5 秒的 wide 视角：村镇、河湖与累计白色航迹；用正常 UI 4× 积累仿真样本，再回到 1× 运行截图，不通过控制租约或注入位姿摆拍。
- 同一连续飞行约 181–182 秒的 wide 视角：不再次 seek、不切控制来源，实际保留至少 8 秒历史再以 1× 截图，核验更长白带；第一张仍用于相同机位的宽度、亮度和绿色山地对照。
- 保持 local/host 控制租约下的 front/side 巡航视角：相机变化不触发机构演示或停止飞行。
- 0.1× 巡航实体叶片，以及完全停车后的无曝光层状态。
- EV50、移动端、机构检查、共享相机和 JSON/Python/HTTP 控制证据。

JSON 附件记录各档帧序号、`renderer.info` 的末次 render pass draw calls / triangles，以及景观、转子显示层和航迹的结构预算。High 后处理会重置计数，其末 pass 的 1 draw / 1 triangle 不代表完整场景；这些数据不用于跨档性能比较。截图必须逐图检查后才用于视觉结论；状态/预算测试通过不能代替像素质量验收。

## 预算的含义

本次软件渲染 CI 的整项 job 上限为 **40 分钟**：此前基线完整 Chromium run 约 18.5 分钟，增加运行中视角、倍率与航迹验证后预留整体执行空间。单个加载/过渡等条件仍有原 30 秒等待边界，行为断言没有因此放宽。该 job 上限不是帧率目标、实际完成时间保证或硬件性能结论。

结构性上限：

- 地景 Low ≤45,000、Medium ≤100,000、High ≤180,000 三角形；有界程序纹理（山区 2 张、海岛 1 张）与实例化批次。
- 每个旋翼曝光显示层 ≤10,000 三角形；双前桨巡航 ≤20,000。这些仅属于显示层，不是整机总面数。
- 白色航迹最多 384 点、固定缓冲、一个透明 draw call；shader 使用局部年龄以避免大时间原点精度损失。

结构预算可以从几何与实例计数得出，`renderer.info` 在当前配置下是末次 render pass 统计；两者都不等于物理显存、真实 GPU 测量或 FPS benchmark。暂不作“在所有设备流畅”之类承诺。

## 边界

所有景观均为程序化虚构场景。白色渐隐带是飞行路径提示，不代表电动无人机必然产生凝结尾迹。超过 0.6 个仿真秒的采样间隔、时间反转、瞬移、低净空或生命周期切换会保守断开旧航迹。

机体 Blend/GLB 保持原字节；转子外观层、地景与路径提示的渲染改善不重新证明机械强度、制造可行性、连续无碰撞或适航性。Blender 完整 rebake 与有限物理采样没有因这次视觉迭代而重新运行。

## 外部位姿不由布景重新裁决

新增地形是视觉场景，不是外部控制碰撞地图。统一外部控制和遥测保留传入位姿；旧 EV50 `flight.command` 的 position/velocity 继续使用 b6736a9 的原有安全包络，不因山地范围变化而默默提高目标高度。低空外控可能进入可见山体，场景净空仅作显示提示。自动改写外部位置以避障不属于本次更新。

## 绿色山地与更长航迹的后续验收

`d4c24893f64beaa39673d1befa336ce5d516d298` 的开发分支 Chromium run `37892002990` 完整 16/16 通过，合入 main 后 run `37895107492` 再次 16/16 通过（24.6 分钟）。这些是后续绿色山地和加宽、提亮、延长白带之前的基线，不能作为新视觉已经通过的证据。基线 front 正交近轴图仍有很淡的三角/折扇叠影；正常 wide 图已验收，但不能据此宣称所有角度都没有瑕疵。

用户反馈之后的景观用例保留原约 173.5 秒截图，再通过正常 UI 4× 分段推进至 176、179、181.1 秒，返回 1× 并等待新渲染帧后拍第二张。实际 `historySeconds > 8`，前后 generation、resetCount 和控制源保持一致，不用伪造采样或再次跳时补长色带。该用例整体上限调整为 300 秒：基线用例实际约 132 秒，另给三段各 30 秒的连续暖场和一张最长 60 秒截图空间；每个行为条件仍为 30 秒，整项 job 仍为 40 分钟。新像素需要同时检查山地是否明显呈绿色、白带是否清楚且更长、是否遮住机体，以及近轴角度叠影是否被提亮放大。

## 公开 Pages 的独立验收

`Deploy SkyCaptain hangar` 部署成功后运行 `scripts/verify-public-pages.mjs`，严格限定到 `https://haifengyue.github.io/sky-captain/`。先逐文件比较实际公共资源与上传构建的 SHA-256（含新旧模型路径），再用 Chromium 在该公共子路径加载 EV50、播放 SkyTrans、访问旧 query 别名并切回 EV50，检查新渲染帧、模型几何、控制源与 shader/HTTP/网络错误，上传 `public-pages-evidence`。这一检查不把本地服务或 HTTP 200 代替公共三维验收。

dot 云浏览器在本次检查时没有可用的 WebGL 上下文，因此它只验证了公开站点入口和 UI；实际公共 GPU 渲染结论以该后部署 Chromium 结果和截图为准。原私有预览保留相同项目与 owner-only 访问，公开 Pages 是单独的已授权发布目标。

`71986de6fddf17b6261b9338f407883fa98923bc` 的开发分支 Chromium run `37899228454` 完整 16/16 通过（25.6 分钟），新绿色山地及加宽白带的正常飞行截图已检查。近镜头的白色核心偏实，正交近轴视角仍有轻微折扇叠影；两张 wide 图的较老尾端在画面之外，不能单靠截图宣称完整消散尾端可见。

## 蓝天与可选山区 / 海岛

旧绿色版本保存在 `archive/green-landscape-20261009`（`71986de6fddf17b6261b9338f407883fa98923bc`）。后续场景在独立 `feature/sky-island-mountain` 开发，继承主分支 QA 历史。天空为一个全屏背景 pass 和固定程序云纹理，不使用墙钟推进；场景选择保留共用根组和原起降参考，旧景观自有几何、材质与实例在切换时释放。

场景结构预算仍为 Low ≤45k、Medium ≤100k、High ≤180k 三角形；山区使用两张纹理（地表与云），海岛一张云纹理。这些是几何/缓冲统计，不是硬件性能或照片级地理真实性保证。CPU 场景测试检查岛岸、LOD 实际三角插值、两机型三条既有航线净空和反复切换的资源释放；旧名义地形/控制包络保持独立。

原 `hangar.spec.ts` 的 16 项仍在独立 40 分钟 job 完整执行，仅将山区纹理数断言由 1 更新为 2（地表细节与云纹理），其余断言和时限保留。新增 `landscapes.spec.ts` 三项使用另一 20 分钟 job，覆盖山区→海岛→山区重复切换、暂停/播放和外控租约/时钟/位姿/相机、同值不重置、真实 Back 与持久页恢复、URL/本地偏好与禁用存储。两个视觉/外控用例各 300 秒，多次页面恢复用例 360 秒；行为条件保持 30 秒，截图 60 秒。公开部署另在原 8 分钟 smoke 内增加 EV50 海岛实渲染与截图。

两场景的蓝天白云、实际岛岸/山区构图和正交相机结果必须检查新提交的真实像素。CPU 测试和前一绿色版本的成功不能代替这一轮视觉验收。
