# 单一完整工程交付说明

交付目标是一个完整当前工程，包含可运行网页、可编辑源模型、生成链、Python 接口及必要复验资源。没有按发行标签拆分的主包或补充资源包，也不要求用户合并多个下载附件。

本轮界面重构已经过当前前端五阶段验收；物理211项与前端88项冻结依赖联合为274项，全部纳入单一完整工程。模型、物理输入及原物理结果逐字节保持，既有作者链、44阶段及模型离线视觉结论按其原范围保留，本轮未再次物理重扫。打包器仍逐项复查本页门槛后才写入ZIP。

## 应包含的内容

- 当前前端、依赖锁、网页静态资源与经过核对的构建输出
- 当前完整 Blender 源、未压缩 GLB、压缩网页 GLB及模型清单
- 同一飞机的独立概念动力部件和其源资产
- 模型生成器、压缩器、正式数据输入及必要许可证记录
- Python 服务、SDK、协议、示例和跨语言测试资源
- 几何、运动、支承、源导出、独立重建、前端与 Python 所需验证脚本和夹具
- 绑定最终文件的报告、输入锁、文件清单和校验结果
- 当前工程中文文档和下载说明

校准合同、保留表面数据、继承基准和测试夹具可能带有原始来源标记。这些标记用于解释证据来源，不代表多架当前飞机或旧版本发行包；只有实际依赖闭合检查才能判断是否必要。

`qa/regenerated/`只纳入当前独立重建验收实际锁定的33个输入/输出文件，用于复查30项生成输入及重建源、运行资产与清单；它不是另一个可编辑工程或历史整机备份。`qa/current/author/source-reexport.glb`用于核对保存源的真实重新导出。虽然这些可复算文件在普通Git忽略规则中排除，最终自包含交付仍依据实际输入锁明确纳入必要部分。

## 不纳入的内容

迭代备份、无关旧模型快照、旧对比媒体、过时说明、多份发行包、候选日志、未被冻结输入锁引用的可复算大型中间数据、`.git`、`.venv`、`node_modules`、凭据、秘密环境文件、用户原始标注图及第三方摄影或视频不进入当前交付。

当前工程在独立目录整理，原工作目录保留供回溯。必要依赖经迁移映射和当前实测报告验证；原证据保持原始字节，初始化路径替换可逆向重建核对原SHA-256。初始化迁移映射作为冻结来源保留；后续UI修改在 `qa/frontend/ui-change-provenance.json` 中另列当前SHA，不再将受影响文件的当前内容冒充纯路径迁移。

## 构建不清空原目录

生产构建为 `tsc -b && vite build --emptyOutDir false`。构建允许更新同名资源，不清空 `dist/`；验证时比较构建前后路径集合，确认没有文件消失。

交付快照选择当前入口引用的构建资源、当前静态源和全部必要冻结输入。原 `dist/` 中未被当前入口使用的旧资源可以不纳入快照，这不表示删除它们，也不将当前快照称为完整 Git 历史镜像。

## 最终完整性门槛

1. 当前模型文件、Blender 源、清单与对应验收报告绑定相同的实际字节数和 SHA-256
2. 几何和前端输入锁覆盖真实依赖，阶段定义、实际命令、退出码与汇总一致，冻结后没有输入漂移
3. 构建入口引用完整，当前 `public/` 静态资产与 `dist/` 对应副本逐字节一致
4. 必要夹具、校准合同、生成输入和继承基准完整随包，迁移引用不指向旧工作目录、私有目录或缺失文件
5. 文件路径合法，没有回退段、重复条目、越界符号链接、凭据或不应分发的素材
6. 单一完整工程清单记录全部交付文件的实际路径、字节数与 SHA-256；归档输出须再次校验内容和解压集合
7. 打包程序自测只证明打包逻辑，不替代模型、网页、浏览器或设备验收

物理汇总位于 `qa/current/results/summary.json`，前端汇总位于 `qa/frontend/summary.json`；两者的输入锁按路径联合并逐项检查SHA-256。`项目信息.json` 绑定真实模型计数、文件字节与这两套报告。精确交付集合与打包工具自测由包内 `PROJECT_MANIFEST.json` 绑定。

在工程根运行 `python3 -B scripts/package_project.py --output /工程外目录/Transwing完整工程.zip`。打包器先完成内存快照的完整核验，再写一个ZIP并逐项复查CRC、SHA与文件集合；不会为了附件大小拆分或漏掉必要依赖。覆盖既有输出须显式添加 `--overwrite`，旧工程和旧文件不会被删除。
